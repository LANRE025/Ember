# Ember Frontend

The web app for **Ember**, a calibrated evening planner. It is a single-page React + TypeScript app built with Vite, styled as a dark-fantasy "system" interface where **Kael**, a shadow-knight coach, guides you through a small nightly loop.

It talks to the Ember backend over HTTP, so the backend must be running (see [`backend/README.md`](../backend/README.md)).

---

## Requirements

- Node.js 20 or newer (with npm)
- The Ember backend running locally (default `http://127.0.0.1:8082`)

---

## 1. Install

```bash
cd frontend
npm install
```

## 2. Point it at the backend

Create `frontend/.env`:

```
VITE_API_BASE_URL=http://127.0.0.1:8082
```

This must match the port the backend runs on. If you leave it out, the app uses `http://127.0.0.1:8082`. Restart `npm run dev` after changing it.

## 3. Run

```bash
npm run dev
```

Open the address Vite prints (normally http://localhost:5173).

Start the backend first. The AI label at the top right shows which provider it is using: `Groq`, `Gemini (Vertex AI)` or `offline mode`.

## Other commands

| Command | What it does |
|---|---|
| `npm run dev` | Development server with hot reload |
| `npm run build` | Type-checks and builds the app into `dist/` |
| `npm run preview` | Serves the production build locally |

## The app

The interface has five tabs and a coach.

| Screen | What it does | Backend calls |
|---|---|---|
| **First run** | Name your goal and why it matters. Kael asks 8 to 10 questions tailored to the goal, then reveals Stretch / Realistic / Floor bands with a description and reason for each. If the AI is unavailable, "Use starter bands" lets you continue. | `POST /setup/start`, `POST /setup/interview`, `GET /setup/status` |
| **Today** | Your goal, the three bands in the goal's own unit, the nightly log (Stretch, Realistic, Floor or Nothing) and your rank. | `POST /logs/log`, `POST /rank/update` |
| **Tonight** | Type a brain dump and Kael turns it into exactly three quests with a tiny first step each. Finishing the shutdown shows the Quest Complete popup. | `POST /ai/shutdown`, `GET /ai/quests/{goal_id}` |
| **Week** | Unlocks after 3 logged nights. Kael asks three questions about your week, and only after the third answer proposes a single change, which you accept. Shows your last 7 days, or a "we'll see by the end of the week" message while you are just starting. | `GET /week/overview/{goal_id}`, `POST /week/start/{goal_id}`, `POST /week/answer`, `POST /week/propose`, `POST /week/respond` |
| **Achievements** | Badge display. Currently a static preview. | none |
| **Reminder** | Preview of the evening reminder, quoting your own "why". | none |
| **Consult Kael** | A chat window opened from Kael's nameplate. Replies are generated by the AI and appear in the same window. | `POST /ai/chat`, `GET /ai/chat/{goal_id}` |

Rules the interface follows:
- The Floor can never be lowered from the interface. Only Ember's weekly proposal can move it, by one step and never to zero.
- A failed AI call never breaks a screen. You see a calm message ("Kael is silent for a moment. Try again.") and can continue. Tonight falls back to three simple quests built from your own dump.

## Project layout

```
frontend/
  src/
    App.tsx             All screens and state
    services/api.ts     Typed API client and the shared error handler
    main.tsx            Entry point
    ember.css           Styling
    assets/             Kael and flame artwork
  index.html
  vite.config.ts
```

`src/services/api.ts` is the only file that knows backend URLs. In a deployed container the backend address is read at start-up from `/config.json` (see `DEPLOY.md`), and locally from `VITE_API_BASE_URL`.

## Troubleshooting

| Symptom | Fix |
|---|---|
| "Cannot reach the Ember server" | The backend isn't running, or `VITE_API_BASE_URL` points at the wrong port. Check `http://127.0.0.1:8082/ai/health` in a browser. |
| First screen appears blank for a moment | The app is checking `/setup/status`. If it stays blank, open the browser console (F12) for the error. |
| "AI: offline mode" in the top bar | The backend has no usable AI provider. Set `AI_PROVIDER` and its key in `backend/.env` and restart the backend. |
| Kael replies "silent for a moment" | The AI call failed. The backend console prints the reason (rate limit, wrong model id, missing key). |
| "Not Found" under the rank | The frontend and backend are out of sync. Pull the latest backend and restart it. |
| Changes to `.env` have no effect | Vite reads `.env` at start-up. Stop and restart `npm run dev`. |
| Week tab says to begin your journey | The Week unlocks after 3 logged nights. For testing, run `python scripts/seed_demo.py` in `backend/`. |
